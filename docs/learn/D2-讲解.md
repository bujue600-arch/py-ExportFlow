## 2. 应用工厂：create_app() 是后端的 "Provider 树"

前端入口是 `createRoot(<QueryClientProvider><BrowserRouter><App/>...)`——把基础设施挂到组件树外层。后端入口 `create_app()` 干同一件事：

```python
app.add_middleware(TraceIdMiddleware)          # ≈ 最外层 Provider：每个请求先过这里
app.include_router(health_router)              # ≈ <Route> 注册
app.include_router(api_router, prefix="/api")
```

**uvicorn 是什么**：Python 的"dev server"（≈ vite dev server 背后的 node）。`python -m uvicorn app.main:app --reload --app-dir server` 意思是：把 `server/` 加进导入路径，找到 `app.main` 模块里的 `app` 对象来服务，文件变动自动重启。

## 3. 装饰器 @router.get：FastAPI 的路由注册

```python
@router.get("/ping")          # ← 这行 = router.get("/ping")(ping_fn) 的语法糖
def ping():
    return {"pong": True}
```

`router.get("/ping")` 返回一个"注册器函数"，它把 `ping` 存进路由表并原样返回函数。和 React 高阶组件 `withRouter(Component)` 是同一个思想：**不修改你，只是把你登记进框架的表**。FastAPI 靠这张表 + 函数签名上的类型注解自动生成 `/docs` 的 Swagger 文档和参数校验——这就是"类型即文档"在后端的形态。

## 4. 信封机制（★ bullet ③ 后端侧，今晚的主菜）

契约要求：所有 `/api` JSON 响应长成 `{code, message, data, trace_id}`。实现分两条路径：

### 4.1 成功路径：EnvelopeRoute 在「路由层」包装

```python
class EnvelopeRoute(APIRoute):
    def get_route_handler(self):
        original = super().get_route_handler()
        async def wrapped(request):
            response = await original(request)     # 执行端点，拿到响应
            ...
            payload = build_envelope(0, "ok", content, trace_id)  # 包信封
            return JSONResponse(payload)
        return wrapped
```

每个路由的处理函数被替换成 `wrapped`——端点本身**只返回 data 本体**，信封统一在一处附加。收益：写业务的人不可能忘包信封、不可能包错形状。

**为什么不用中间件改写响应体？**（面试高频）`BaseHTTPMiddleware` 拿到的 body 是**只能读一次的流**，要改写得先读完再重造响应；而 D4 的 SSE 与文件下载是**流式响应**，根本不该被改写。在 route 层包装，拿到的还是端点返回值，非 JSON 响应（`media_type` 非 json 或无 `body`）直接放行，天然兼容流。

### 4.2 今天踩的真实坑（写进面试故事）

我最初的判断是 `isinstance(response, JSONResponse)`，测试当场打脸：**路由函数带返回类型注解**（`def ping() -> dict[str, object]`）时，FastAPI 把注解当作 `response_model` 处理，返回的是**裸 `Response`** 而非 `JSONResponse`，判断失效、信封漏包。修复：

```python
media_type = response.media_type or ""
raw_body = getattr(response, "body", None)
if not media_type.startswith("application/json") or raw_body is None:
    return response          # 流式/文件直通
```

教训（面试可讲）：**对框架的隐式行为做类型断言前，先验证真实对象形态**；防御性判断要看"能力"（media_type + 有无 body）而不是"类名"。

### 4.3 错误路径：AppError + 全局异常处理器

业务代码里只抛 `AppError(3001, "导出超上限", data={...})`，四个异常处理器把**所有错误出口**归一成信封：

| 异常 | 映射 |
|---|---|
| `AppError` | 按抛出时给的 code/http_status |
| 参数校验失败（FastAPI 自动 422） | code 1001 + `data.details` |
| `HTTPException(404)` | code 2001（映射表） |
| 未捕获异常 | code 5000，**固定文案不泄漏堆栈**（安全细节） |

对照前端：这就是 axios 响应拦截器在后端的镜像——**错误形状的统一是前后端共同的契约**（api-contract §2），前端统一请求层（D3）才能"只处理一种错误"。

## 5. trace_id 链路（bullet ③ 的另一半）

```
请求进入
  ├─ 读 X-Request-Id 头，没有就 uuid 生成
  ├─ request.state.trace_id = tid     # 给信封用（同一次请求内传递）
  ├─ trace_id_var.set(tid)            # ContextVar：给日志用（跨函数传递）
  ▼
业务执行 → logger.info(...)           # 日志格式里自动带 [trace_id]
  ▼
响应头 X-Trace-Id: tid 回传 + 信封 body 里也有 tid
```

**ContextVar ≈ 前端的 AsyncLocalStorage**：每个并发请求有独立的值，日志 Filter 从中取号注入记录，async 任务间不会串号。前端拿到 tid 展示在报障文案里（D3 实现），用户报障 → 后端 `grep trace_id` 直接命中整条日志链——这就是简历那句"凭 trace_id 串联前后端日志"的机制。

## 6. 依赖注入：get_db（B 明天天天用）

```python
def get_db():
    with Session(engine) as session:   # with ≈ try/finally 自动关
        yield session                  # yield：请求期间把 session 借给路由
```

路由声明 `db: Session = Depends(get_db)`，框架调 get_db 把结果注入参数——**控制反转**，路由不关心引擎从哪来。测试时 `app.dependency_overrides[get_db] = 换成临时库`，零 mock 就能隔离数据库（B 的测试会用到）。对照 React：`useContext` 之于 props drilling，`Depends` 之于手动传参。

## 7. 前端骨架为什么这么分

- **按 feature 而不是按类型组织**：`features/assets/` 内聚组件+hooks+测试，删一个域只动一个目录；跨域的东西必须"升舱"到顶层，逼人回答"这真的通用吗"。
- **QueryClientProvider 挂最外层**：所有组件共享一个缓存实例，D6 的 setQueryData 精准更新（bullet ②）依赖这一点。
- **retry: false**：演示与测试要确定性，重试交给专门的错误处理（D3 统一请求层）。

## 8. 面试官可能怎么问（附答题要点）

**Q1：统一响应结构你在哪一层实现？中间件行不行？**
要点：路由分发层（自定义 APIRoute）；中间件改 body 面临"流只读一次"和与 SSE/文件流冲突的问题；错误侧用全局 exception handler，两条路径汇成同一信封出口。加分：讲今天的 `response_model` 坑——说明真的踩过。

**Q2：trace_id 怎么贯穿一次请求？**
要点：透传或生成 → request.state（请求内）+ ContextVar（跨函数）→ 日志 Filter 注入每行日志 → 响应头回传 + 信封携带 → 前端报障文案展示 → 用户报障可 grep。说清"为什么要两处存"（state 给信封、ContextVar 给日志）。

**Q3：前后端错误形状为什么要契约化？**
要点：前端只面对一种错误对象（ApiError）才能做统一的 UI 与文案；错误码表分段（1xxx 参数/2xxx 资源/3xxx 业务/5xxx 兜底）让定位不用读 message；这是排障契约不是风格偏好。
