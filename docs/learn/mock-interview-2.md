# 模拟面试 · 第二轮：架构权衡与压力追问

> 这轮的问题没有标准答案，考的是"你怎么想"。每题先给结论，再给权衡，最后给"如果重来"。

## 权衡题

**Q1：为什么队列不上 Redis/Celery？**
参考：明确说这是教学级取舍——单进程、万级任务量、SQLite 轮询够用；保留队列语义三要素（抢占原子、租约心跳、至少一次+幂等去重）；升级路径 SKIP LOCKED→Redis BRPOP→Celery 且 claim/lease/heartbeat 接口不变。**反问需求规模**："200 创作者的量级，引入三个中间件的运维成本换什么？"——面试官想听的是判断力不是技术清单。

**Q2：为什么选 SSE 不选 WebSocket？**
参考：单向推送场景；SSE 是 HTTP 语义（过代理友好、文本协议可读、原生 Last-Event-ID）；双向需求（取消任务）出现时才值得升级 WS。加分：原生 EventSource 重连策略太粗所以自建状态机——"用原生能力，拿回策略权"。

**Q3：job_version 为什么不直接用时间戳？**
参考：时钟不可靠（多实例时钟漂移、NTP 跳变）；版本号是逻辑序不是物理时间，只需全序不需对齐现实；比较语义简单（严格大于）；int 比较比字符串时间解析廉价。

**Q4：为什么前端要把选择逻辑写成纯函数而不是放组件里？**
参考：可测性（表驱动全组合）、可复用（快照语义被 D5 全选复用）、防漂移（组件里写逻辑会被 UI 改动裹挟）；"逻辑下沉 lib，组件只做投影"。

## 压力题

**Q5：「你这些测试都是假的——FakeEventSource、假时钟、mock fetch，测试通过能说明什么？」**
参考：承认 mock 测不到真实网络，但状态机的正确性=时序逻辑正确性（退避参数、降级阈值、升级条件），这些恰恰只有假时钟能确定性验证——真网络反而不可复现；真实链路有 e2e_smoke（真 uvicorn）+ 手动演示脚本兜底。**测试分层：逻辑层用假 IO 求确定性，集成层用真服务求真实性**。被逼急了反问："您建议怎么对'断网 5 秒后自动降级'写一个可重复的真网络测试？"

**Q6：「信封、错误码、trace_id，这套东西加起来代码量不小，小项目值得吗？」**
参考：算账——信封中间件+请求层约 200 行，换来：前端错误处理单一形状（每个调用点省 5-10 行 if/else）、报障从"看截图猜"到"一个号查全链路"、错误码分段让定位有目录。**契约的价值随调用方数量指数增长**；项目小所以成本两天，公司项目调用量大所以回报更大。

**Q7：「你们这个 AI 协作流程，不就是让 AI 写代码然后自己测吗？谁来保证 AI 没埋雷？」**
参考：三道闸——①规格先行：契约钉死形状，AI 的产出有机器可校验的对错标准（测试即规格执行）；②体量门禁+规则文件：单文件 300 行强制拆分，AI 的大坨输出进不了仓库，规则文件版本化约束生成边界；③人工把关：每个 PR 有把关清单和评审记录（PR#4 评审推动契约演进是真案例）。关键句："我不监督 AI 的每行代码，我监督**规格与门禁**——可验证性前置，而不是事后人肉审。"

**Q8：「简历写'独立实现前后端'，你这后端不就是 CRUD 吗？」**
参考：这后端的考点不在 CRUD——任务表即队列的抢占/租约/心跳、版本+事件原子的单一入口、幂等三分支、SSE 重放窗口、双形状下载。每个都是并发/一致性问题的最小实现。承认范围（单进程教学级）+ 展示理解深度（升级路径）。

## 复盘方法

每题录音 3 分钟 → 回听时对照三个检查项：①先给结论了吗 ②有权衡不是布道吗 ③给出代码/PR 位置了吗。三连不过关的题，回对应讲解文档重读再录一遍。
