## 练习 1：cancelFlag.ts

```ts
export interface CancelToken {
  cancelled: boolean;
}

export function createCancelToken(): CancelToken {
  return { cancelled: false };
}

export function applyIfCurrent<T>(token: CancelToken, value: T, apply: (value: T) => void): void {
  if (!token.cancelled) {
    apply(value);
  }
}
```

测试：

```ts
import { describe, expect, it, vi } from "vitest";
import { applyIfCurrent, createCancelToken } from "../cancelFlag";

describe("applyIfCurrent", () => {
  it("token未取消_数据被应用", () => {
    const apply = vi.fn();
    applyIfCurrent(createCancelToken(), "最新结果", apply);
    expect(apply).toHaveBeenCalledWith("最新结果");
  });

  it("token已取消_过期数据被丢弃", () => {
    const token = createCancelToken();
    const apply = vi.fn();
    token.cancelled = true; // 模拟 useEffect cleanup 已执行、慢响应才回来
    applyIfCurrent(token, "过期结果", apply);
    expect(apply).not.toHaveBeenCalled();
  });
});
```

它在 React 里的真实用法（对照简历原话）：

```ts
useEffect(() => {
  const token = createCancelToken();
  fetchList(filter).then((data) => applyIfCurrent(token, data, setData));
  return () => { token.cancelled = true; }; // cleanup：本轮作废
}, [committed]);
```

要点：`cancelled` 在**闭包里**，每轮 effect 有自己的 token，这就是"闭包取消标志"四个字的展开。

## 练习 2：弄红测试

改 `code > 0` 后，`request` 的这些用例会红：

- `成功_解包_data本体`（code=0 不满足 `> 0`... 实际上 0 > 0 为 false，成功仍通过！）——**仔细想**：真正红的是带错误码的用例吗？`code=3001` 时 `3001 > 0` 为 true，行为不变……

正确观察：这个改动可能**一个测试都不红**！因为 `code !== 0` 与 `code > 0` 在"code 为非负整数"的现有用例下行为等价。

这本身就是答案的一半：**现有测试没覆盖 code 为负/非数的场景，所以行为变化检测不到**——测试只锁你想到要锁的行为。若真要区分两者，需要补一个 `code: -1` 的畸形响应用例。

思考题（code 0→200 的波及面）：

1. `api-contract.md` 契约文档（§1 信封定义、§2 错误码表）——最先改；
2. `client.ts` 的 `body.code !== 0` 判断；
3. `client.test.ts` 所有成功用例的 okEnvelope；
4. 后端 `envelope.py` 的 `build_envelope(0, "ok", ...)`；
5. 后端 8 个测试的断言。

一改动横跨两个代码库五个位置——这就是为什么改 code 语义必须走契约 PR：**没有单一事实源，就没有安全变更**。
