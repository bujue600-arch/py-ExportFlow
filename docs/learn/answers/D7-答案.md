# D7 练习参考答案（时间线与现象对照）

## 断网自愈时间线（第 2 步的参考记录）

```
T+0s    创建导出 → 徽章「实时」，进度条随 job_updated 推进
T+2s    DevTools Offline：
        - EventSource 立即 error → 第1次失败，1s 后重连（失败）
        - 第2次失败，2s 后重连（失败）
        - 第3次失败 → 徽章「轮询降级」，Network 出现 active_only 请求（3s 间隔）
T+~8s   进度仍在推进（轮询在干活，用户无感）
T+20s   Online → 徽章回「实时」（或稍后 SSE 后台重连成功时），轮询请求停止
```

若你的观测与上面有出入（比如降级出现更慢），检查：Offline 后 EventSource 的 error 触发时机因浏览器而异——**这正是"真实行为不确定、所以要用假时钟锁定逻辑"的现场证据**。

## API 层演示的现象结论（第 2' 步）

1. SSE 三连事件：QUEUED(v1) → RUNNING(v2) → FAILED(v3, code 3003)——每次可观测变更版本+1；
2. 同键重发：返回**同一个** job id（幂等命中），不是新建；
3. `/docs` 里 Try it out 一次 404：body 是信封（code 2001）且带 trace_id——错误也讲"信封话"。

## 什么时候算"扛得住"

三轮自测标准（来自 mock-interview-1 的使用说明）：
- 每题：先结论 → 有权衡/证据 → 说得出代码位置；
- 10 个 SSE 场景能脱口而出至少 7 个；
- 压力题 Q5/Q7 各有 30 秒版本答案。
到不了就去读对应 D 讲解文档——库存都在，缺的只是复述次数。
