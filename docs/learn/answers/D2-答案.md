## 练习 1：build_envelope 改动

```python
from datetime import datetime   # 文件顶部 import 区

def build_envelope(code: int, message: str, data: Any, trace_id: str) -> dict[str, Any]:
    """构造信封字典。"""
    return {
        "code": code,
        "message": message,
        "data": data,
        "trace_id": trace_id,
        "server_time": datetime.now().isoformat(timespec="seconds"),
    }
```

测试断言（加在 `test_成功响应_被包装为信封` 里）：

```python
    assert body["server_time"]  # 非空即可；时间是动态的不硬编码具体值
```

要点：

1. 为什么改测试：测试锁的是**行为**，行为变了测试不变 = 门禁失效。CI 红了不可怕，可怕的是"改了行为没人知道"。
2. 为什么 `timespec="seconds"`：isoformat 默认带微秒，测试与肉眼比对都不友好。
3. 思考题：`server_time` 放信封里意味着**每个响应**都带，这是契约变更（api-contract §1 的形状变了）——真项目里要先提契约 PR。练习里我们不改契约文件，但你应该意识到这条线。

## 练习 2：现象结论

1. `/healthz` → `{"status":"ok"}`，没有信封（豁免清单里的端点）；
2. `/docs` → Swagger UI，FastAPI 从路由函数签名自动生成；
3. `/api/nothing` → HTTP 404，body 是信封：`code: 2001`（HTTPException 404 的映射），`message: "Not Found"`；
4. 响应头 `X-Trace-Id` 与 body `trace_id` 相同——一个给机器（前端请求层读取展示），一个给人（Network 面板肉眼排查）；
5. 指定 `X-Request-Id: my-trace-001` 后，响应体、响应头、**后端日志**三处都是同一个号——这就是"凭一个号串起一次请求的全部痕迹"。

常见踩坑：

- Windows 下用 `curl`（不带 .exe）若报乱码/行为怪，用 `curl.exe`（PowerShell 的 curl 是 Invoke-WebRequest 别名）；
- 改了 `envelope.py` 但响应没变：`--reload` 偶尔不灵，Ctrl+C 重启 uvicorn。
