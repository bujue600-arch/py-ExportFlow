## 1. 任务表即队列：一个教学级的严肃取舍

不上 Celery/Redis，任务表就是队列：

```python
# job_repo.claim_next：抢占下一个任务
WHERE status == QUEUED OR (status == RUNNING AND lease_until < now)
```

- **抢占**：worker 把任务翻成 RUNNING 才执行，两个 worker 不会领到同一个（UPDATE 的原子性）；
- **租约（lease）**：领走时打上 30 秒租约，`bump_and_publish` 每次推进进度自动续租（心跳）；worker 崩了租约到期，任务可被重新抢占——**防卡死**。

面试正解是把这个取舍讲清楚：万级任务量、单进程、无外部依赖，轮询 SQLite 完全够；真正要解决的是**正确性**（抢占原子性、租约、幂等、版本），而不是堆中间件。升级路径（SKIP LOCKED → Redis BRPOP → Celery）不改变 `claim/lease/heartbeat` 这个接口——设计隔离了实现。

## 2. job_version：单一入口递增（bullet ② 的根）

```python
def bump_and_publish(session, job, **updates):
    for k, v in updates.items(): setattr(job, k, v)
    job.job_version += 1          # 版本先于广播
    commit()
    bus.publish("job_updated", _event_data(job))  # 事件携带新版本
```

为什么**必须**单一入口（RULES-backend #8）：

- 版本递增和事件广播必须是原子的两步——分开写，就会出现"版本加了但事件没发"或反过来；
- 多处代码都能改状态时，版本依赖读取时的值做 +1，并发下会互相覆盖（丢更新）；
- 单一入口 = 状态机的唯一关口，review 只需要盯一个函数。

这就是乐观锁思想在事件流上的落地：**版本是事实的序号，事件是版本的通知**。D6 前端拿 `event.job_version <= 本地版本 → 丢弃` 做乱序防护，前提就是这里严格单调。

## 3. 幂等键（bullet ④ 的服务端半边）

```python
payload_hash = sha256(规范化JSON)          # 字段排序后的确定性哈希
existing = 按idempotency_key查
  ├─ 无     → 校验载荷 → 建任务
  ├─ 同哈希 → 返回原任务（重试安全）
  └─ 异哈希 → 3002（同键不同意图，是 bug 不是重试）
```

细节：**幂等判定在参数校验之前**——重试一个"上次就参数非法"的请求，应该得到上次那个错误，而不是先被 422 拦下。规范化 JSON（sort_keys）保证相同语义载荷哈希一致。

## 4. SSE 通道（bullet ① 的服务端半边）

连接的首块由三种情况决定：

```
Last-Event-ID = X ──> X 在窗口内？ ──是──> 重放 seq > X 的所有事件
        │                    └─否/无ID──> snapshot（全量任务 + 版本地图）
之后：job_updated 增量推送；15s :ping 心跳；断开退订
```

- **全局事件日志**（deque, 窗口 512）就是重放的数据源——"先记日志再扇出"，掉线者的补课和在线者的直播读同一份数据；
- snapshot 带 `max_job_version_map`：客户端重放窗口外丢失太久时，一次校准所有任务的版本；
- `bye` 事件：服务端主动关闭前广播，客户端视同断连进入重连状态机（D6 前端消费）。

**为什么 SSE 端点在信封路由类下却不被包装**：`EnvelopeRoute` 按 `media_type + body` 判断，`text/event-stream` 直通——D2 设计的流式兼容今天兑现了。

## 5. 今晚的两个真实 bug（面试故事，都值得讲）

**Bug 1：include_router 不继承 route_class。** jobs 路由器的路由根本没走信封类——响应是裸 DTO。D2 没暴露是因为当时 `/api` 下还没有真实业务路由（骨架测试的盲区：test_envelope 用的是直挂路由）。修复：每个子路由器显式 `route_class=EnvelopeRoute`。教训：**基础设施的测试要覆盖它的真实接线方式，不是理想接线方式**。

**Bug 2：TestClient 流式响应挂起。** httpx2 传输层对无限流缓冲不吐数据，SSE 测试整个卡死。修复：不走 HTTP，直接消费端点返回的异步生成器断言协议输出。教训：**测试基建遇到平台限制时，退一层测协议而不是硬刚传输层**（HTTP 层留到 D7 用真实 uvicorn 端到端验证）。

## 6. FastAPI 语法点

- **`async def` vs `def` 路由**：async 跑在事件循环上，def 被丢进线程池。我们的任务端点全是 async——因为 `bus.publish` 要操作 `asyncio.Queue`，必须和订阅者同处一个事件循环，线程池里的 sync 路由摸不到它；
- **lifespan**：`yield` 前后就是启停钩子——建表、启动 worker、关服务时广播 `bye`；
- **`Header(default=None, alias="Last-Event-ID")`**：连字符请求头映射到下划线参数。

## 7. 面试官可能怎么问（附答题要点）

**Q1：job_version 为什么要单一入口递增？绕过会出什么问题？**
要点：版本+广播必须原子；多处 +1 并发丢更新；review 收敛到一个函数。延伸：这就是把"约定"升级为"结构保证"。

**Q2：SSE 客户端重连，服务端怎么保证它不丢事件、也不重放错？**
要点：Last-Event-ID + 全局 seq 重放；窗口外转 snapshot 全量校准；事件本身带 job_version，客户端还能再兜一层（双保险）。强调"不重放错"靠客户端版本比对——服务端只保证"多发不少发"。

**Q3（压力题）：你这队列就是个轮询数据库的循环，也配叫消息队列？**
要点：承认形态（单进程轮询），讲清它保留了队列的**语义三要素**——抢占原子性/租约心跳/至少一次执行+幂等去重；讲升级路径接口不变；最后反问需求规模（200 创作者/万级任务），拒绝为简历堆中间件才是工程判断。
