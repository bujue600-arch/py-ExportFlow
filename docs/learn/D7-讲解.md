# D7 讲解：收官——把五条 bullet 串成一次导出的完整旅程

> 今晚没有新框架，只有三样东西：端到端冒烟、架构总览、两轮模拟面试。读讲解前先读 `docs/architecture/overview.md` 的图（10 分钟）。

## 1. e2e_smoke：真服务器上的全链路验证（D4 欠账兑现）

```python
# scripts/e2e_smoke.py 的四步断言
1. POST 创建（信封 code=0）+ 同键重发（幂等返回原任务）
2. GET /api/events 真流式 → 首块 snapshot 含刚建的任务
3. sleep 2.5s → worker 执行占位执行器 → 详情 FAILED/3003
4. 404 详情 → 信封 2001 + trace_id
```

为什么它重要：TestClient 的流式缓冲让我们绕开了 HTTP 层（D4），但"SSE 在真实 TCP 上能流起来"始终欠一个证据——今晚补上，**一次通过**。顺带的小改进：`EXPORTFLOW_DB` 环境变量让端到端测试用独立临时库（不加这层，冒烟会污染开发库）。

面试说法："我的测试分三层——纯函数表驱动（63 个）、协议级直连生成器（SSE）、真实服务器 e2e（uvicorn 子进程）。每层解决的问题不同，缺一层就有一种 bug 藏身处。"

## 2. 全链路串讲：面试官问"讲讲你这个项目"的标准答案

照 `overview.md` §2 的五步旅程讲，90 秒版本：

> "导出是长时任务，我的工作是把'创建→执行→进度→下载'整条链路做到可观测、可自愈、可排障。筛选层输入永不触发请求、查询以最近一次提交为准（三层状态）；选择层三态模型表达跨页全选，谓词+排除集而非 ID 枚举，幂等键防重；传输层 SSE 推进度、断连自动退避重连三次后降级轮询、网络恢复自动升级；一致性靠 job_version 乐观锁+SSE 仅通知 HTTP 校准；排障靠统一信封+trace_id 一号串前后端日志。全部行为有 100+ 测试和 CI 门禁锁定。"

每一步被追问时，跳到对应 mock-interview-1 的 bullet 章节。

## 3. 两轮模拟面试怎么用（未来两周）

- **第一轮（细节）**：每天 2 个 bullet，遮住答案口述+录音，对照要点打分；
- **第二轮（压力）**：Q5/Q7 是最可能被问的，练到能 30 秒内给出结论+证据+反问；
- 三检查项：先结论？有权衡？给得出代码位置？

## 4. 面试官可能怎么问（收官三题，也是答辩三题）

**Q1：这个项目最难的 technical 点是什么？**
要点候选（挑你真有体感的讲）：连接状态机的降级/重连并行设计（契约矛盾被测试逼出来的故事）；或 D2 的 response_model 坑+include_router 坑（信封漏包两次踩坑与修复）。**讲踩坑比讲成功值钱**。

**Q2：如果流量涨 100 倍，你的架构哪里先崩？**
要点：SQLite 写锁先崩（单写者）→ 换 Postgres 不改代码（SQLModel 抽象）；EventBus 进程内 → 换 Redis pub/sub，端点协议不变；worker 单进程 → 多进程靠租约抢占天然安全（已经设计好）；前端无状态可水平扩。**答案不是"都能扩"，而是"知道崩点在哪、换什么、动几行"**。

**Q3：AI 在这个项目里扮演什么角色？你自己做了什么？**
要点：AI 是执行者，规格/契约/规则/门禁/评审是人定的——"规格先行、AI 实现、人工把关"不是口号：契约 v1.0→v1.2 的每次演进都有 PR 和评审记录（PR#4 是 B 的 AI 写的、我评审推动契约修订的真实案例）。诚实边界：代码大量由 AI 生成，但**决策、踩坑定位、契约演进判断**是这个项目的"人的部分"，也是你面试时真正的底气。
