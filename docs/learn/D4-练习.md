## 练习 1（核心）：给状态机加一个 `mark_progress` 入口（约 15 分钟）

场景：B 的执行器每处理 500 条要上报一次进度。为避免 B 直接算 progress 写字段，你在 `server/app/services/job_service.py` 里加一个**走单一入口**的便捷函数：

```python
def mark_progress(session: Session, job: ExportJob, *, processed: int, total: int) -> ExportJob:
    """按已处理数计算进度百分比并推进（total=0 时进度恒为 0，不能除零）。"""
```

要求：

1. progress = `round(processed / total * 100)`，`total <= 0` 时 progress = 0；
2. 同时更新 `processed_count`、`total_count`；
3. **必须**内部调用 `bump_and_publish`（不许直接改字段）。

在 `server/tests/test_jobs_api.py` 末尾加两个 pytest：

1. `test_mark_progress_正常计算百分比`：processed=250, total=1000 → progress=25，且 job_version 增 1；
2. `test_mark_progress_total为0_不炸且进度为0`。

验收：

```powershell
pytest server/tests -q
```

## 练习 2（体验）：亲眼看 job_version 三连跳（约 10 分钟）

开两个终端（仓库根目录）：

```powershell
# 终端 1：启动后端（worker 默认开启）
python -m uvicorn app.main:app --app-dir server

# 终端 2：连上 SSE 通道（-N 禁用缓冲，实时看）
curl.exe -N http://127.0.0.1:8000/api/events
```

保持终端 2 盯着，浏览器打开 `http://127.0.0.1:8000/docs`，找到 `POST /api/export-jobs` 点 Try it out，请求体填：

```json
{"mode": "SELECTED_IDS", "selected_ids": ["a1", "a2"], "format": "csv"}
```

`Idempotency-Key` 随便填个 `test-001`，Execute。

**观察终端 2**：应看到三个 `job_updated` 事件接连出现——创建（QUEUED, version=1）→ 抢占（RUNNING, version=2）→ 占位执行器失败（FAILED, version=3）。把这段输出复制保存，明晚日报我要你用自己的话描述"版本为什么是 1→2→3"。

看完 `Ctrl+C` 断开（观察终端 1 日志里的 access 行都带 trace_id）。
